# Contributing to flutter_ui_debug

Thank you for your interest in contributing! This guide will help you get started.

## How to Contribute

### Reporting Bugs

1. Check if the bug has already been reported
2. Create a new issue with:
   - Clear description
   - Steps to reproduce
   - Expected vs actual behavior
   - Flutter version and package version

### Suggesting Features

1. Check the [Roadmap](../../development/roadmap.md) for planned features
2. Open an issue with the `enhancement` label
3. Describe the feature and its use case

### Contributing Code

1. Fork the repository
2. Create a feature branch
3. Make your changes
4. Add tests if applicable
5. Ensure all tests pass
6. Submit a pull request

## Development Workflow

1. **Set up your environment** - See [Setup Guide](../setup/)
2. **Follow code style** - See [Code Style Guide](../code-style/)
3. **Write tests** - Add tests for new features
4. **Update documentation** - Keep docs in sync with code
5. **Submit PR** - Include description of changes

## Code Style

- Follow Dart style guide
- Use meaningful variable names
- Add documentation comments
- Keep functions focused and small
- Write self-documenting code

## Testing

- Run `flutter analyze` before submitting
- Run `flutter test` to ensure tests pass
- Test on multiple Flutter versions if possible

## Pull Request Process

1. Update CHANGELOG.md with your changes
2. Update relevant documentation
3. Ensure CI checks pass
4. Request review from maintainers

## Questions?

Feel free to open an issue or discussion on GitHub!
